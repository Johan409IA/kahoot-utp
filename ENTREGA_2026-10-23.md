## Cómo retomar

Desde la raíz del proyecto, en PowerShell:

```powershell
./scripts/start-local.ps1
```

Esperar el mensaje de arranque de Spring Boot y abrir
[http://127.0.0.1:8080/](http://127.0.0.1:8080/).
El script inicia PostgreSQL y luego mantiene el backend en primer plano.
Selecciona Java 25 y prepara las herramientas locales si faltan.
No hace falta ejecutar `npm install` para servir el frontend integrado.

Para cerrar: primero **Ctrl+C** en la terminal del backend y después:

```powershell
./scripts/start-local.ps1 -StopDatabase
```

Para iniciar únicamente PostgreSQL, usar `-DatabaseOnly`.
No reinicializar ni borrar `.local/postgres-data` para reiniciar la aplicación.

## Qué se hizo

### Revisión del proyecto

Se revisaron los controladores, DTO, modelos, repositorios, servicios, seguridad,
inicializadores, pruebas y documentación funcional/API. El proyecto original
contenía el backend de una plataforma de micro-retos educativos con roles de
estudiante UTP, docente UTP y usuario externo.

### Frontend

Se implementó una SPA en español con módulos JavaScript y CSS en
`src/main/resources/static`, servida por el mismo Spring Boot. Usa navegación por
hash y solicitudes a `/api` en el mismo origen. **No se implementó Angular**:
la documentación inicial lo mencionaba como propuesta; la implementación actual
no requiere compilación ni dependencias npm de ejecución.

Incluye:

- Inicio, cursos, catálogo y filtros por curso, tema, nivel y texto.
- Registro, verificación, login, recuperación y restablecimiento de contraseña.
- Práctica con selección múltiple, ordenamiento de bloques, predicción de salida
  y selección de fragmentos; evaluación en servidor, retroalimentación, reintentos,
  solución asistida e historial por reto.
- Progreso, puntos de dominio, insignias y preferencias de accesibilidad.
- Herramientas docentes para preguntas, alternativas, explicaciones, quizzes
  ordenados y salas con PIN, estados, participantes, anulaciones y clasificación.
- Diseño responsive, foco visible, salto al contenido y ordenamiento mediante
  botones para no depender del arrastre.

Archivos principales:

| Ruta | Función |
| --- | --- |
| `src/main/resources/static/assets/app.js` | Navegación, sesión y vistas principales. |
| `src/main/resources/static/assets/practice.js` | Práctica y evaluación remota. |
| `src/main/resources/static/assets/teacher.js` | Gestión docente. |
| `src/main/resources/static/assets/api.js` | Cliente HTTP, JWT y errores. |
| `src/main/resources/static/assets/core.js` | Utilidades, etiquetas y rutas. |
| `src/main/resources/static/assets/demo.js` | Adaptador aislado de demostración. |

| `scripts/preview.mjs` | Vista previa independiente y proxy local a la API. |
| `frontend-tests/` | Pruebas unitarias del frontend. |

La sesión se conserva en `sessionStorage`, con expiración y limpieza ante 401.
El frontend envía la respuesta seleccionada a `/intentos/evaluar`; no calcula
la respuesta correcta a partir del catálogo público.

### Maven, Java y PostgreSQL

- `mvnw.cmd`: se corrigió el acceso a `Target[0]` cuando la propiedad es nula en
  Windows. El wrapper selecciona `.tools/java` y una caché absoluta en `.tools/m2`,
  evitando el intento de crear `C:\.m2\repository`.
- Se instaló **Eclipse Temurin 25.0.4.1** para el proyecto; Maven usa **3.9.16**.
  El Java global del equipo no se modificó y puede seguir mostrando otra versión.
- Se preparó **PostgreSQL 18.6** portable, sin instalar un servicio global,
  con base `adaptcode_utp` en `127.0.0.1:5433`.
- Se resolvió el fallo del selector NIO de Java/Tomcat en este entorno de Windows
  pasando `-Djdk.net.unixdomain.tmpdir=.local` al backend de desarrollo.
- `application.properties` admite `ADAPTCODE_DB_URL`; el perfil `local` restringe
  Spring Boot a `127.0.0.1`.
- Se añadieron `scripts/setup-java.ps1`, `scripts/setup-postgres.ps1` y
  `scripts/start-local.ps1`. `.tools/` y `.local/` están excluidos en `.gitignore`.

Las credenciales de PostgreSQL están en `.local/database-credentials.xml`,
cifradas con Windows DPAPI para la cuenta que las creó. No se incluyen contraseñas
ni tokens en esta entrega. En otro equipo, preparar su propio entorno con el
script; el XML cifrado no es una credencial portable. Conservar los datos y ese
archivo en este equipo para poder reutilizar la base existente.

### Tipografía

Se sustituyeron los tamaños pequeños de la interfaz por una escala en `rem`:
texto principal normal de **16 px**, opción Grande de **18 px** y Muy grande de
**20 px**. Las preferencias cambian la base del texto sin aplicar zoom al diseño.
También se reajustaron tarjetas, paneles y disposición móvil para acomodarlo.

## Límites pendientes para quien continúe

No dar por implementadas estas capacidades:

1. **Partida sincronizada del estudiante:** faltan endpoints para obtener las
   preguntas y alternativas de sala y conocer/controlar la pregunta actual.
   La interfaz implementa ingreso, estado y ranking; no simula el juego faltante.
2. **Actualización de salas:** es manual; no hay WebSocket/SSE.
3. **Clonado docente:** el servicio actual copia metadatos; hay que completar
   alternativas y retroalimentaciones de la copia.
4. **Preguntas docentes avanzadas:** su DTO no admite código base ni bloques.
5. **Insignias:** el backend otorga automáticamente Primer paso y Perseverante;
   las otras tres solo aparecen como obtenidas si la API las devuelve.
6. **Historial global y errores por revisar:** no existe un endpoint agregado;
   actualmente se consulta el historial por micro-reto.
7. **Verificación por correo:** la versión actual devuelve códigos en la API;
   no se implementó envío de correo real.
8. No hay una auditoría formal WCAG ni un despliegue de producción verificado.

Si la próxima tarea es completar las salas, empezar revisando el contrato del
backend y sus estados; no resolverlo mostrando datos ficticios o pidiendo al
estudiante que declare si acertó. No se inició ese trabajo en esta sesión.
